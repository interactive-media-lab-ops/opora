# Опора

**Платформа пошуку лідерів для реформи ППП у ЗСУ на основі принципів лідерства.**

Кандидат проходить кілька шарів оцінювання — анкету, опитувальник, голосове інтерв'ю, збирає рекомендації. ШІ перевіряє ці дані за методологією, яку методист збирає на візуальному канвасі як граф промтів. HR отримує профіль кандидата з радаром за принципами лідерства як **основу для рішення** — саме рішення лишається за людиною. Пілот працює на Культурних Силах.

## Як це працює

```
 Кандидат                       Бекенд + ШІ                          HR
 ────────────────────────       ─────────────────────────────        ────────────────────────
 1. Анкета                 ──►  транскрипція голосу (Whisper)   ──►  профіль кандидата
 2. Опитувальник                граф промтів (LLM, паралельно)       радар за принципами
 3. Голосове інтерв'ю           фінальні висновки + бали             вердикт, нотатки, PDF
 4. Рекомендації (4 посилання)  журнал подій і аудит                 власні списки, Excel
```

### Ролі

| Роль | Що робить |
|---|---|
| **Методист** | Створює методології: поля анкети, питання опитувальника та інтерв'ю, питання рекомендаторам, граф промтів. |
| **HR** | Дашборд, база кандидатів із фільтрами, картка кандидата (**лише фінальні висновки**), вердикт і приватні нотатки, запрошення, власні списки з експортом у Excel, PDF профілю. |
| **Кандидат** | Проходить етапи в будь-якому порядку, роздає посилання рекомендаторам. Результатів аналізу не бачить. |
| **Рекомендатор** | Без реєстрації, за одноразовим посиланням відповідає на питання про кандидата анонімно. |
| **Адмін** | Акаунти методистів і HR, скидання 2FA, запити на видалення даних, перегляд кабінетів інших ролей. |

## Архітектура

```
                ┌──────────────────────────┐
   браузер ───► │  web  (nginx, статика)   │  React 19 · Vite · TypeScript · Tailwind v4 · PWA
                └────────────┬─────────────┘
                             │ /api
                ┌────────────▼─────────────┐        ┌──────────────┐
                │  api  (FastAPI, async)   │ ◄────► │  postgres 16 │
                └────────────┬─────────────┘        └──────────────┘
                             │ задачі (Redis)
                ┌────────────▼─────────────┐        ┌──────────────┐
                │  worker  (Celery)        │ ◄────► │  NEAR AI     │  транскрипція + граф промтів
                └──────────────────────────┘        └──────────────┘
```

- **Бекенд:** FastAPI + SQLAlchemy 2 (async) + Alembic; фонові задачі — Celery на Redis; JWT, TOTP-2FA, аудит дій.
- **Фронтенд:** React 19, React Query, React Flow (канвас графа промтів), Tailwind v4 на токенах дизайн-системи, service worker для офлайн-режиму кандидата.
- **ШІ:** усі виклики моделей — через [NEAR AI Cloud](https://cloud.near.ai) (OpenAI-сумісний API): аналіз і транскрипція. Прямі виклики Anthropic/OpenAI доступні лише для локальної розробки (`ALLOW_DIRECT_AI=true`).
- **Дані:** Postgres; аудіозаписи — у файловому сховищі (`storage/`); усе на власних серверах.

## Швидкий старт

Потрібні Docker і Docker Compose.

```bash
cp .env.example .env
# у .env задайте JWT_SECRET (openssl rand -hex 32) і NEAR_API_KEY
docker compose up -d --build
```

- Застосунок: <http://localhost:8090>
- API та Swagger: <http://localhost:8765/api/docs>

Міграції та демо-дані застосовуються автоматично під час старту `api`.

Без ключа ШІ платформа теж працює: кандидати проходять етапи, а транскрипція та аналіз завершуються керованою помилкою, яку видно в картці кандидата. Після додавання ключа — «Повторити невдалі кроки».

## Демо-акаунти й демо-дані

| Роль | Пошта | Пароль |
|---|---|---|
| Адмін | `admin@opora.example` | `ChangeMe123!` |
| Методист | `methodologist@opora.example` | `ChangeMe123!` |
| HR | `hr@opora.example` | `ChangeMe123!` |
| Демо-кандидати | `*@opora.example` (список у кабінеті адміна) | `ChangeMe123!` |

Паролі задаються змінними `SEED_*_PASSWORD` у `.env`; у продакшні змініть усе до першого запуску. Свій адмін: `docker compose exec api python -m app.create_admin пошта --name "Ім'я"`.

Сід (`python -m app.seed`, ідемпотентний) наповнює кожен кабінет: дві активні методології з графами, чернетка й архів, кандидати на всіх етапах (включно з прикладом збою вузла), вердикти, нотатки HR, голосові записи й транскрипти, запрошення. Усі дані вигадані; демо-висновки позначені моделлю `demo-seed`.

- `SEED_DEMO_DATA=false` — лише три службові акаунти.
- `SEED_DEMO_DATA=rich` — розширений набір для огляду дизайну: методології з 3 і 8 осями, довгі тексти, збої аналізу, відгуки в усіх станах, HR з увімкненою 2FA (ключ `JBSWY3DPEHPK3PXP`). Лише для локального огляду.

## Ключові рішення

- **Рішення ухвалює людина.** ШІ формує висновки й бали, HR ставить вердикт; усе логується.
- **Закритий периметр ШІ.** Моделі викликаються тільки через NEAR AI; дані кандидатів не йдуть у сторонні SaaS.
- **Методологія — це конфігурація, а не код.** Методист збирає граф промтів на канвасі; після активації поля й питання заморожуються (усі кандидати в рівних умовах), промти й граф можна змінювати й перезапускати аналіз.
- **HR бачить лише фінал.** Вузли без вихідних стрілок — фінальні; тільки їхні висновки доступні HR, зведений бал — середнє їхніх балів. Повні результати кожного вузла — лише адміну.
- **Анонімність рекомендаторів.** Кандидат бачить тільки лічильник «N / 4», HR — відгуки з роллю без імен і часу.
- **Захист від prompt injection.** Дані кандидата передаються моделі окремим блоком з інструкцією вважати їх даними, а не командами.
- **Найменші привілеї.** Методист не бачить даних кандидатів і не чує записів; імперсонувати можна лише демо-акаунти.

## Функціональність

### Граф промтів

Вузол = один промт. Стрілки задають порядок: вузол запускається, коли завершені всі його попередники, незалежні гілки виконуються паралельно, цикли заборонені (перевірка на фронтенді й бекенді). Кожен вузол отримує всі дані кандидата й висновки попередників; може повертати бал 1–10 — тоді модель відповідає структуровано. Вузли з балом методист розмічає «віссю аналітики» і «джерелом» (самоподача / розмова / відгуки) — з них у профілі будується радар (3–8 осей) або смуги.

### Кабінет кандидата

Не майстер, а хаб: картки етапів з рубежем «N / M», етапи незалежні й проходяться в будь-якому порядку. Анкету можна редагувати завжди; опитувальник та інтерв'ю — «Пройти заново» зі збереженням попередньої спроби в журналі. На картках видно версію методології.

### Розмова (голосове інтерв'ю)

Діалог у вигляді чату: питання по одному, відповідь текстом або голосом (ліміт задає методологія, не більше 15 хв), одна відповідь на питання. Відповіді спершу зберігаються на пристрої (IndexedDB) і надсилаються автоматично, коли є зв'язок; повтор запиту ідемпотентний (`client_request_id`).

### PWA та офлайн

Застосунок встановлюється на пристрій і відкривається без мережі: service worker кешує лише статичну оболонку, запити `/api/*` не кешуються. Кандидат офлайн бачить хаб і розмову з останніх даних (лише для власника, прибираються при виході). HR, методист і адмін офлайн бачать сторінку «Немає зв'язку»: персональні дані кандидатів на пристрої не зберігаються.

### Рекомендації

Кандидат отримує 4 одноразові посилання `/r/<токен>` (30 днів, можна перевипустити). Рекомендатор без входу обирає роль (керівник / колега / підлеглий) і відповідає текстом; «Недостатньо знаю людину» закриває посилання без відгуку. Надіслані відгуки додаються в контекст аналізу.

### Безпека

JWT із refresh-токенами; TOTP-2FA для HR і адміна (секрети зашифровані ключем з `JWT_SECRET`); журнал аудиту (експорт PDF, імперсонація тощо); запит на видалення власних даних з адмінською чергою.

### Адмін

Перемикається між кабінетами вкладками в шапці. У вкладці «Кандидат» — вхід у кабінет демо-кандидата зі справжнім збереженням або перегляд будь-якої методології без збереження.

## Структура коду

```
backend/
  app/api/          роутери FastAPI: auth, candidate, results, hr_notes, hr_lists, audio,
                    methodologies, recommendations, users, account, config
  app/models/       SQLAlchemy-моделі
  app/schemas/      Pydantic-схеми запитів і відповідей
  app/services/     бізнес-логіка: граф, аналіз, контекст для промтів, рекомендації,
                    candidate_views (серіалізація кандидатів), pdf, export, storage, totp
  app/services/ai/  провайдери моделей (claude, whisper, near)
  app/tasks/        Celery: транскрипція, виконання вузлів графа
  alembic/          міграції
  tests/            pytest (117 тестів, SQLite in-memory)

frontend/src/
  api/              HTTP-клієнт, типи відповідей
  components/ui/    примітиви дизайн-системи (Button, Field, Card, Badge, Alert …)
  components/       складені компоненти (список кандидатів, нотатки, плеєр, запис …)
  pages/            сторінки за ролями: auth, candidate, hr, methodologist, admin, recommend
  lib/              офлайн-кеш, PWA, назви етапів
  demo/             mockApi для демо без бекенду
```

## Якість коду

```bash
cd backend
uv run ruff check .          # лінт (конфігурація в pyproject.toml)
uv run ruff format .         # форматування
uv run pytest                # тести

cd frontend
npm run typecheck            # tsc
npm run lint                 # oxlint
npm run format               # prettier
```

## Розробка без Docker

```bash
docker compose up -d postgres redis        # база й черга

cd backend
uv sync
uv run alembic upgrade head
uv run python -m app.seed
uv run uvicorn app.main:app --port 8765    # API
uv run celery -A app.tasks.celery_app:celery worker --pool=threads --concurrency=4   # воркер

cd ../frontend
npm install
npm run dev                                # http://localhost:5173 (проксі /api → :8765)
```

> Воркер запускається з `--pool=threads`: на macOS стандартний пул (`spawn`) не працює з Celery-задачами, а задачі тут — I/O (запити до API й БД), тож потоків достатньо.

### Змінні середовища ШІ

```
AI_PROVIDER=near                          # аналіз (near | anthropic)
TRANSCRIBE_PROVIDER=near                  # транскрипція (near | openai)
NEAR_API_KEY=...
NEAR_MODEL=anthropic/claude-sonnet-5-5    # будь-яка модель з tools: curl https://cloud-api.near.ai/v1/models
NEAR_TRANSCRIBE_MODEL=openai/whisper-large-v3
NEAR_TRANSCRIBE_LANGUAGE=uk               # необов'язково
```

Якщо модель не приймає примусовий `tool_choice`, запит повторюється в режимі `auto`, а за відсутності виклику функції JSON береться з тексту відповіді. Ліміт аудіо — 25 МБ (mp3, wav, webm, flac, ogg, m4a).

## Що далі

- Надсилання запрошень листом (SMTP) — зараз посилання копіюється вручну.
- Видалення кандидатів і аудіо за запитом (зараз — лише черга запитів для адміна).
- Автотести фронтенду (бекенд покритий тестами; інтерфейс перевірено вручну).
