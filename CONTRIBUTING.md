## Гілки

- `main` — стабільна гілка, з неї запускається прототип. Захищена: пушити можуть лише Maintainers, форс-пуш вимкнено.
- Усе інше — у своїх гілках через MR. Назва: `тип/коротко-латиницею`:
  - `feat/` — нова можливість (`feat/hr-invites`)
  - `fix/` — виправлення (`fix/audio-retry`)
  - `ui/` — рестайл без зміни логіки (`ui/hr-profile`)
  - `docs/` — документація (`docs/q-71`)
  - `chore/` — налаштування, залежності, інфраструктура
  - `s8/…` — зрізи етапу 8 дизайну (історична назва, продовжуємо для етапу 8)
- Одна гілка — одна задача. Перед MR оновіть гілку з `main` (`git pull origin main` або rebase, якщо гілка тільки ваша).

## Коміти

- Українською. Перший рядок — що змінено і навіщо, з ID рішення чи задачі, якщо є: `Зріз 2 (етап 8): рекомендатор за дизайном КС — R1/R3/R4, C5 «Рекомендації»`.
- Якщо змін кілька — коротко перелічіть їх у тілі коміту.
- Ідентичність git для цього репо: `git config user.name` / `git config user.email` (робоча пошта).

## Merge request

- Відкривайте MR у `main`, опис — за шаблоном (підставляється сам; якщо ні — «Choose a template» → `Default`).
- Невеликі MR краще за великі: один зріз або одна BR-n.
- Ревʼюер — за таблицею вище. Усі обговорення мають бути закриті перед злиттям.
- Злиття — merge commit (історія зберігається). Squash — на розсуд автора; при squash відредагуйте повідомлення коміту — GitLab за замовчуванням бере заголовок першого коміту гілки. Гілку видаляємо після злиття.

## Що ніколи не комітимо

- `.env`, ключі API, паролі, токени. Шаблон змінних — лише `.env.example` без значень.
- `_private/` — чужий прототип із **реальними персональними даними військових**. Не відкривати, не копіювати.
- Реальні персональні дані будь-де: у seed, тестах, скріншотах, описах MR. Демо-дані — лише вигадані (DD-03).
- Шрифти (`frontend/public/fonts/`) — ліцензії: UAF Sans (DD-27), CY Grotesk (X-16).
- Аудіозаписи кандидатів (`storage/audio/`).

Випадково закомітили — не пушіть, виправте коміт локально або напишіть Max. Уже запушили секрет — вважайте його скомпрометованим: змініть ключ і повідомте команду (видалення з історії ключ не рятує).

## Правила продукту, які стосуються коду

- **Закритий AI-периметр:** усі виклики моделей, зокрема транскрипція, — лише через NearAI. Нових прямих викликів OpenAI/Anthropic не додаємо (поточний стан — X-26, відкрито).
- UI не підробляє поведінку: якщо поля чи ендпоінту ще немає — функцію сховано або кнопка недоступна з причиною, у коді `// TODO(backend-requests: BR-n)`.
- Змінили контракт API — оновіть `BACKEND-TASKS.md`.
- Методологію оцінювання команда не створює: ми робимо інструмент і вносимо готову методологію.
